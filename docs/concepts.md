# Concepts and terminology

This guide assumes basic familiarity with quantum circuits, but no knowledge of
this project's experiments. The task is to choose a two-dimensional arrangement
of computing and routing resources, compile a circuit on it, and reduce the
space and time reserved for that computation.

## Circuits, tiles and layouts

A **logical qubit** is a qubit in the input algorithm. A **patch** represents an
encoded logical qubit in a surface-code architecture. **Lattice surgery** performs
operations through measurements involving these patches. The compiler translates
a circuit into a schedule of such operations.

A **tile** is one cell of the compiler's rectangular grid. It is an abstract
resource location, not one physical qubit. A **layout** specifies the tile types
and where each logical qubit starts. In the custom layouts, `Q` denotes a data
patch, `r` a routing cell, and `M` an abstract magic-state supply location.
Routing cells provide space for operations connecting patches.

A **magic state** is an auxiliary quantum state used to implement non-Clifford
operations such as T gates. An `M` cell models a deterministic source of these
states. Its one-tile representation does not include the physical footprint of
a complete distillation factory. Other symbols in native layouts belong to the
upstream compiler's layout format; do not reinterpret them as `M` cells.

**Clifford+T synthesis** expresses a circuit using Clifford gates and T gates.
General rotations may require approximation by a sequence of these gates.
**QASM** (Quantum Assembly Language) is the text format used for input circuits.

## Area, slices and space–time volume

**Area** is grid height multiplied by grid width, measured in **tiles**. Every
cell in the rectangle counts, including data patches, supplies and routing cells
that happen to be idle. It is not the number of occupied cells or physical qubits.

A **time slice** is one completed frame of the compiler's schedule. The reported
slice count measures the duration of the compiled circuit in this model. It is
neither the number of gates nor a duration in seconds. A compiler slice should
not be equated with a physical error-correction cycle.

**Space–time volume** is area multiplied by the number of completed time slices,
measured in **tile-slices**. The full rectangular area is counted for every slice;
this metric does not sum only the cells active at each instant.

For example, a 6-by-7 grid has area 42 tiles. If compilation takes 218 slices,
its volume is 42 × 218 = **9,156 tile-slices**. A 9-by-9 grid taking 162 slices
has volume 81 × 162 = **13,122 tile-slices**. The first uses about 30.22% less
volume even though it takes more slices. These numbers illustrate why the docs
report area, duration and their product separately.

There is **no hard area cap** in the geometry search. Larger grids can be tried;
the volume objective penalizes their area unless reduced duration compensates.
An **observed Pareto frontier** contains evaluated layouts for which no other
evaluated layout is at least as good in both area and duration and strictly
better in one. It describes the observed tradeoff, not every possible layout.

## Local compilation and scheduling

**Local compilation** means enabling liblsqecc's `--local` instruction
decomposition, which breaks supported higher-level instructions into explicit
local operations. **Nonlocal compilation** here means running without that flag.
The two configurations can produce different durations and compilation failures.
Neither configuration alone is a complete physical hardware simulation.
“Local search” has a different meaning: an optimizer proposing changes near its
current candidate. It does not describe the compiler decomposition setting.

A **scheduler** chooses when operations execute, subject to dependencies and
resource availability. **Wave** is the liblsqecc scheduler selected by `-P wave`.
It is independent of the `--local` setting. All results on the benchmark page use
wave scheduling **with local compilation enabled**.

**Native layouts** are generated by liblsqecc itself using `compact`,
`compact_no_clogging`, or `edpc`. **EDPC** expands to **Edge-Disjoint Paths Compilation**, the algorithm described
in [Beverland, Kliuchnikov and Schoute](https://arxiv.org/abs/2110.11493). Here it
identifies the upstream `edpc` layout family. Selecting that layout does not select the separate `-P edpc` scheduling
pipeline. **Custom layouts** are produced by this project's search and evaluated
with the same underlying compiler. See the [integration contract](integration.md)
for the preprocessing settings needed to reproduce a score.

## Geometry and logical identity

**Geometry optimization** changes dimensions and tile placement. **Mapping
optimization** changes which logical qubit occupies each data location. The
current search supports both. Moving an initial assignment is not an instruction
to insert physical SWAP gates into the circuit.

The compiler numbers data locations in **row-major order**: left to right across
each row, then top to bottom. Logical qubit 0 need not occupy compiler location 0.
The exported `identity.json` records the relationship, and `mapped-circuit.qasm`
relabels circuit wires to match it. Keep these files with their grid.

A **bundle** means the **layout output folder** containing these related files;
it is not a special file format. The folder contains `layout.txt`, `layout.svg`,
`identity.json`, `original-circuit.qasm`, `mapped-circuit.qasm` and `resources.json`.
The public optimizer also saves results and compilation evidence. The
[quickstart file table](quickstart.md#inspect-the-result) explains each file.

## Reading experiment reports

A **baseline** is a reference layout against which a result is compared. The
benchmark compares each custom result to the lowest-volume successfully compiled
native layout for that circuit. A failed compilation has no usable volume;
it is never assigned zero duration or counted as a victory by itself.

A **seed** initializes the pseudorandom choices used by a search. Different seeds
can find different layouts. A **pooled best** selects the best observed result
across the stated seeds and supply counts; it is not the typical outcome of one
run. A **warm start** is a previously optimized layout used as an initial
candidate. Its earlier optimization cost remains relevant to fair comparisons.

A **score request**, also called an **oracle query**, asks the evaluator to score
a candidate. A **cache hit** reuses a saved score for exactly matching inputs and
settings. A **charged slot** counts against the search budget even when a cache
hit, failed compilation or invalid proposal avoids a new compiler invocation.
A **replay** recompiles an exported winner afresh to check that the saved grid
and matched circuit reproduce its score.

## Algorithm abbreviations

| Term | Meaning in this project |
|---|---|
| SA | Simulated annealing: randomized search that can accept worse intermediate layouts |
| PT | Parallel tempering: multiple searches at different acceptance temperatures, with exchanges |
| RL | Reinforcement learning: training a policy to choose actions from reward feedback |
| PPO | Proximal policy optimization: the training algorithm used by the experimental geometry policy |
| CNN | Convolutional neural network: a network that processes spatial grid features |
| HPO | Hyperparameter optimization: searching over algorithm settings, such as learning rates |
| API | Application programming interface: the Python functions used to integrate this package |

The [algorithm guide](algorithms.md) explains these methods and distinguishes
supported optimization functions from experimental training interfaces.
